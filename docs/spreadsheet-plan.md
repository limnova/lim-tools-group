# 在线表格实施方案

## 产品定位

在 Lim Tools 中实现浏览器里的电子表格，参考飞书与钉钉表格的工具栏、公式栏、网格和底部工作表标签。第一阶段服务单人编辑；评论、权限和多人实时协作按后续阶段推进。

参考资料：[飞书表格](https://docs.feishu.cn/sheets)、[飞书工具栏](https://www.feishu.cn/hc/zh-CN/articles/594614613907)、[钉钉表格](https://alidocs.dingtalk.com/product/sheet)。这些产品的全部能力不作为首版验收范围。

## 第一阶段与验收

| 功能 | 验收行为 |
| --- | --- |
| 文件管理 | 新建空白表格或预算示例；列表搜索；打开、重命名、删除；独立地址可再次打开 |
| 网格编辑 | 中文界面；键盘输入、选区、复制粘贴、撤销重做；插入删除行列和调整尺寸 |
| 格式 | 字体、颜色、对齐、边框、数字格式、合并单元格、冻结行列 |
| 公式 | 引用单元格与范围，修改源数据后重算；至少验证乘法与 SUM |
| 工作表 | 新建、切换、重命名、复制和删除，刷新后保留 |
| 数据处理 | 排序、筛选、查找替换 |
| 持久化 | 编辑后自动保存、手动保存、保存状态；刷新与服务重启后数据保留 |
| 失败恢复 | 保存失败可重试；未保存时离开有提示；旧版本保存返回冲突，不覆盖更新 |
| 文件交换 | CSV 导入为新文件，导出当前工作表；JSON 备份包含整本工作簿的公式、样式和插件状态 |

## 技术方案

- 前端沿用 Vite + React 19 + TypeScript，按需加载 Univer 1.0.3 的开源 Sheets 内核及筛选、排序、查找替换预设。所有 Univer 包保持相同版本。公式、快捷键、样式和工作表操作交给同一内核，应用层只负责文件管理与保存。
- 服务端沿用 Go + Gin，提供 `/api/v1/workbooks` 列表、新建、获取、更新与删除接口。工作簿包含 `id`、`name`、`revision`、时间戳和完整 Univer 快照。
- 第一阶段使用服务端文件存储：每份工作簿单独 JSON 文件；临时文件写入并同步成功后替换正式文件；同进程内串行化修改；客户端更新与删除必须提交当前 `revision`，过期请求返回 HTTP 409。
- 存储位置通过 `LIM_TOOLS_WORKBOOK_DIR` 配置，默认 `./data/workbooks`，运行数据不提交 Git。启动服务不访问任何现有 MongoDB 或 PostgreSQL 环境。部署单实例时必须挂载持久卷并备份该目录。
- 文件存储仅支持一个服务进程独占目录。后续换 PostgreSQL repository、增加身份与权限时保留应用 API 契约。当前为一个共享工作区，文件列表没有用户隔离。
- 开发环境由 Vite 将 `/api` 代理到 Go；部署时前端和 API 应在同一域名。首版不包含公网部署、用户登录、权限、多人协作、评论、图表或原生 Excel `.xlsx` 导入导出。
- CSV 只交换当前工作表的值，不携带样式、多表或公式；JSON 用于完整恢复。导入限制文件体积、网格尺寸与已填单元格数；CSV 文本不执行公式，CSV 导出保护可能被 Excel 执行的文本。

## 视觉方案

编辑区域占满窗口，文档标题和保存状态在上方，工具栏与公式栏紧接网格，工作表标签在底部。文件列表采用紧凑行列表，减少非编辑内容占用。

- 颜色：纸白 `#ffffff`、浅灰 `#f5f7fa`、深墨 `#142334`、辅助灰 `#64748b`、松绿 `#1b6b54`、浅绿 `#e9f4ef`。
- 字体：中文使用系统 PingFang SC / Microsoft YaHei；界面文字使用 Segoe UI；数字遵循单元格设置。
- 布局：标题、工具和内容左对齐，表格保持足够可视宽度；窄屏收纳文件操作，网格可以横向滚动。
- 设计复核：不添加营销首屏、统计卡片或虚构协作者；可辨识的元素是绿色表格标记，其余界面保持安静。首屏提供空白表格和真实的预算示例入口。

## 后续阶段

1. 在表格编辑与保存体验稳定后，接入持久数据库、用户身份、文件级读写权限、历史版本以及 Excel 文件交换。
2. 评论：以工作簿 / 工作表 / 单元格范围为锚点，支持讨论串、回复、解决与通知。
3. 多人协作：先明确 Univer 协作模块的许可与部署成本，再确定 OT / CRDT 或其服务端方案；实现在线状态、光标、增量操作同步、断线重连与冲突处理。整份快照加版本号只防止覆盖，不能代替实时协作。

## 验证

- Go 测试覆盖实际文件持久化、重开存储、版本冲突、并发写入、无效输入和 HTTP 契约；运行 `go test -race ./...` 与 `go vet ./...`。
- 前端执行 TypeScript 构建和 oxlint。
- Playwright 使用真实 Go 接口验证新建、编辑、公式、样式、工作表操作、保存刷新、导入导出、冲突和失败重试；截图检查桌面与窄屏布局。
- `browser_pointer.py` 验证行列标题右键菜单的插入、删除、行高与列宽，并通过保存后的服务端快照检查结果。
