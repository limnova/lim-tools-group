# 嵌套仓库路由

## 目标

从聚合仓库根目录工作时，把任务稳定路由到实际目标 Git 仓库的最新指令与 skills。此 skill 只负责发现和透传，不复制任何具体项目规则。

## 路由流程

1. 根据用户明确范围、目标文件、分支、diff 或调用链识别实际涉及的路径。只定位与任务有关的仓库，不遍历加载全部子仓库规则。
2. 对每个目标路径定位其所属的最近独立 Git 根，包括普通子目录仓库和 submodule。若目标仍属于当前聚合仓库，则直接使用当前仓库规则。
3. 对每个下层目标仓库，完整读取从该仓库 Git 根到目标路径适用的 `AGENTS.md` / `AGENTS.override.md` 指令链。当前会话没有自动加载子仓库指令时，必须手动补读后再行动。
4. 根据用户请求、实际改动和目标仓库 `AGENTS.md`，查看该仓库 `.agents/skills/*/SKILL.md` 的名称与描述。决定使用某个 skill 后，完整读取其 `SKILL.md` 及当前任务要求的 references，并按其流程执行。
5. 若目标仓库本身仍是聚合仓库并提供自己的 router，继续按其规则向更深层目标仓库下钻，直到到达实际负责代码或文档的 Git 根。
6. 跨仓库任务分别应用各仓库的开发、审查、测试和验证规则，保留各自证据边界，最后汇总端到端结果。

## 边界

- 子仓库的 `AGENTS.md` 和 skills 是对应项目规则的事实来源；本 skill 不维护项目路径表、技术栈规则、报告模板或领域清单。
- 不因聚合仓库中存在多个 submodule 就扩大用户授权范围，也不把未涉及仓库纳入检查或修改。
- 只修改聚合仓库自身的文档、gitlink、submodule 配置或工作区配置时，不加载无关子仓库规则。
- 子仓库缺失、未初始化、目标 Git 根不明确或规则文件无法读取时，先完成安全的只读定位；仍无法确定时报告缺口，不复制、猜测或静默替代目标仓库规则。
- 个人资料和个人 skills 可以作为当前用户的可选输入，但不得成为团队成员执行子仓库任务的必需依赖。
